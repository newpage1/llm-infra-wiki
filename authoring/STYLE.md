# 文风规范（去 AI 腔）

本站正文是**技术文档**，不是公众号文章。所以通用的「去 AI 味」规则要筛选着用：
**删虚词、去套话、说人话**适用；**砍掉结构、加第一人称、段段讲故事**不适用——
八小节骨架是刻意设计的，路径:行号 是本站的立身之本。

改稿的前提：**只改措辞，不改事实、不删信息、不动锚点**。
一句都看不明白的句子，宁可留着，也不要改成另一句看不明白的。

改完必须过：`bash tools/verify.sh` 与 `node tools/style_audit.js`。

---

## 一、术语表：不要把比喻当术语

### 1.1 「接缝」→ 按语境换掉

「接缝」是英文 seam 的直译，在插件语境里指**宿主留给插件的接管位置**。
问题是它被当成专有名词用了 67 次，而全文没有一处解释过它。

| 语境 | 改成 |
|---|---|
| 宿主留给插件的接管位置（vllm-ascend 全页的主线） | **扩展点** |
| 两层之间的契约面（如 L1MemoryDesc 与 L2） | **接口** |
| 两个模块/层次接壤的地方 | **交界** |
| 表格表头 `\| 接缝 \| 方向 \| 出处 \|` | `\| 接口 \| 方向 \| 出处 \|` |
| `接缝 A` / `接缝 B` 这种编号指代 | **路径 A / 路径 B** |
| 「不制造接缝，只回答接缝上该放谁」 | 「不制造扩展点，只回答扩展点上该放谁」 |

**vllm-ascend 页统一用「扩展点」**，并在首次出现处给一句定义：
> 宿主 vLLM 主动留出的接管位置——插件不修改宿主代码，只往这些位置上放同名实现。

### 1.2 「真正的」→ 删或换

「这层真正的开销在 X」里的「真正的」几乎不携带信息。改成：

- 「这层真正的开销在 X」→「这层的开销在 X」（若前文已在排除别的可能，则保留一次）
- 「这条不是可选的—它是真正的接缝」→「这条不是可选的——它是唯一的接口」

**同一段里最多出现一次**，且只在确实要排除误解时用。

## 二、句式：拆掉模板

### 2.1 「负责 / 不负责」表标签 → 「做什么 / 不做什么」

现在的写法有两处毛病：标签公式化；而且「不负责 | 不搬字节」是双重否定，
读起来要先加一层否定再减一层。

| 现在 | 改成 |
|---|---|
| `\| **负责** \| 维护对象 → 分片 → 位置的目录 \|` | `\| **做什么** \| 维护对象 → 分片 → 位置的目录 \|` |
| `\| **不负责** \| 不搬字节——那交给 Transfer Engine \|` | `\| **不做什么** \| 搬字节——那交给 Transfer Engine \|` |
| `\| **不负责** \| 不做副本策略、不做选主 \|` | `\| **不做什么** \| 副本策略、选主 \|` |

注意：改成「不做什么」之后，**单元格里开头的那个「不」要去掉**，否则又是双重否定。

### 2.2 「不是…而是…」→ 拆成两句

「不是 A，而是 B」是全站第二多的句式（188 处）。连用会让整篇变成同一个节奏。

> 原：它不是一个可选的方便方法，而是与 L2 的接口。
> 改：它与 L2 之间的接口，不是可选的方便方法。

> 原：这不是「顺便提供的信息」，而是 L2 零拷贝的前提。
> 改：这是 L2 零拷贝的前提，不是顺便带上的信息。

**判据**：一段里出现两次以上，就把其中一次拆开或删掉。

### 2.3 「一句话：」「这就是」「这正是」→ 删

- `一句话：**它把…**` → 直接写结论，不要「一句话：」这个引子
- `这就是「不改宿主」的那个扩展点` → `「不改宿主」靠的就是这个扩展点`
- `这正是它能在…下保持可用的原因` → `所以它能在…下保持可用`

### 2.4 「值得注意（的是）」→ 删

后面跟的通常不是注意事项，而是一句正常的说明。删掉引子，句子照常成立。

### 2.5 「一句话」在 `lead` 里的滥用

83 处 `lead` 以「一句话：」开头。`lead` 本身就是导语，不需要再声明一遍。
直接给结论即可。

## 三、不能碰的东西

| 不能碰 | 为什么 |
|---|---|
| `**读图**：` | 校验器要求带图块的 html 里必须有「读图」二字 |
| 代码围栏内容 | 要跟仓库原文逐字一致 |
| `路径:行号` | 本站的立身之本；改一个字符就失去锚点 |
| SVG 里的文字 | 改坏了 `lint_svg.py` 会报重叠；且 SVG 内不能出现 `**` `%%` `~~~` |
| 八小节顺序与标题 | 校验器强制 |
| `%%标识符%%` | 那是代码里的名字，必须与仓库一致 |

同时在改的过程中**不要**：
- 引入 `**` `%%` `~~~` 到 SVG 里
- 写出 `%%a % b%%` 这种「`%%` 中间带 `%`」的写法（渲染器会漏字面量）
- 让粗体跨行（渲染器逐行做行内解析）
- 在表格单元格里用 `%%|%%`（`|` 会把表格切断）

## 四、改完怎么验证

```bash
node tools/style_audit.js        # 看指标有没有降下来
bash tools/verify.sh             # 结构、渲染、SVG 三项
```

`style_audit.js` 里 **「锚点总数」只许增不许减**——它是「有没有在改的过程中
把带行号的论断删掉」的守门人。数字掉了说明丢了信息，不是文风变好了。
